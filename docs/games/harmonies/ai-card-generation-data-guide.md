# ข้อมูลการ์ด Harmonies สำหรับส่งให้ AI สร้างภาพ

- `ai-card-generation-data.json` ครบ 53 ใบ: สัตว์ปกติ 32, Nature’s Spirits 10, ทีเร็กซ์โปรโม 1, เสียงกระซิบ 10
- `ai-card-generation-selected-4.json` เฉพาะทีเร็กซ์ แมลงปอสายน้ำ เห็ดริมน้ำ และจระเข้

ข้อมูลมาจาก Catalog และ scoring engine ของโปรเจกต์นี้ ชื่อภาษาไทยเป็นชื่อเรียกในโปรเจกต์ ไม่ใช่ชื่อทางการที่พิมพ์บนการ์ด ข้อมูลภาพและฟอนต์ต้องแนบ reference ที่อนุมัติควบคู่ไปด้วย

## ฟิลด์หลัก

- `cards[].name_th`, `subject_key`, `card_type`: ชื่อ ชนิดสัตว์/วัตถุ และประเภทการ์ด
- `scoring`: คะแนน สูตร เงื่อนไข และ scenario สำหรับวาดภาพคิดคะแนน
- `scoring.score_track`: ค่าและลำดับที่ต้องวาดในกรอบคะแนน
- `habitat.cells`: พิกัด q/r ชั้นโทเคน จุดวางคิวบ์ และข้อยกเว้นอาคาร
- `source_stack_bottom_to_top`: ข้อมูลดิบจาก Catalog
- `render_stack_bottom_to_top`: ลำดับชิ้นที่ต้องวาดจริง จากล่างขึ้นบน
- `stack_rule`: เงื่อนไขที่ตรงกติกา โดยเฉพาะฐานอาคารที่ใช้แทนกันได้
- `artwork.layout.cells`: ตำแหน่งฐาน ฝาโทเคนแต่ละชั้น และจุดสัมผัสคิวบ์สำหรับจัดภาพ
- `artwork.layout.draw_order_back_to_front`: ลำดับวาดจากด้านหลังมาด้านหน้า

## พิกัดบนภาพ

พิกัด `artwork.layout` อยู่ในช่วง 0–1 และเป็น **คำแนะนำการจัดภาพที่คำนวณขึ้น** ไม่ใช่พิกัดที่ถอดจากภาพต้นฉบับ และไม่เปลี่ยนกติกา q/r ใช้ uniform scale ทั้งกลุ่มเท่านั้น

```text
pixel_x = normalized_x × ความกว้างภาพ
pixel_y = normalized_y × ความสูงภาพ
```

ตัวอย่าง `x=0.4, y=0.8` บน Large 900×1290 คือ x=360, y=1032 px

`base_center` คือกึ่งกลางฐาน ส่วน `token_layers[].cap_center` คือกึ่งกลางผิวฝาแต่ละชั้น ไม่ใช่จุดเดียวกันในแกนตั้ง เพราะชั้นมีความหนา `cube.contact_point` คือจุดสัมผัสล่างสุดของคิวบ์กับฝาชั้นบน ต้องวางทับลายฝาและมีเงาสัมผัส ไม่ใช่ใช้เป็นจุดกึ่งกลางรูปคิวบ์

ตำแหน่งตัวอย่างทำสำหรับ Large 300:430, มีแถบขวากว้าง 13⅓% และจัดกลุ่มกลางพื้นที่ภาพที่เหลือ เมื่อทำ Small ให้ยึด q/r และจำนวนชั้นเดิม ขยายทั้งกลุ่มได้แบบ uniform พร้อมย้ายคะแนนลงขวาล่างและแสดงตัวคูณเฉพาะกองหลายชั้น

## ข้อควรอ่านก่อน Generate

1. สัตว์ปกติ: คะแนนเป็นค่าตามจำนวนคิวบ์ที่วาง เช่น จระเข้ 1/2/3 คิวบ์ = 4/9/15 คะแนน **ไม่ใช่** 4+9+15 กรอบจากบนลงล่างเป็น 15,9,4
2. สัตว์วิเศษ: `source_points:[0]` เป็นข้อมูลภายใน ห้ามวาดคะแนน 0 ต้องใช้ `scoring.scenarios` เช่น แมลงปอกลุ่มน้ำอย่างน้อย 2 ช่อง → กลุ่มละ 7
3. เสียงกระซิบ: วาดช่อง `2/5` สองช่อง คิวบ์แต่ละชิ้นคิด 2 เมื่อเดี่ยว หรือ 5 เมื่อร่วมช่องกับคิวบ์สัตว์/Spirit ไม่ใช่คะแนนสะสม 2 แล้ว 5
4. อาคาร: รหัส `building` บางใบแทนอาคารสูงสองชั้น ต้องอ่าน `render_stack_height` และ `stack_rule` ฐานใช้แดง/ลำต้น/หินได้ ภาพตัวอย่างในชุดข้อมูลเลือกฐานหิน
5. ห้าม mirror รูปแบบ ห้ามสลับ q/r ห้ามนับคิวบ์เป็นอีกชั้นของโทเคน
6. สัตว์วิเศษ/ไดโนเสาร์มี scenario ต่างกัน ห้ามคัดลอกคะแนนของสิงโตไปใช้กับทุกใบ

## ข้อความส่งให้ AI พร้อม JSON และรูป Reference

> สร้างภาพการ์ดจาก record ที่ระบุใน JSON นี้ ใช้ habitat.cells และ render_stack_bottom_to_top เป็นข้อมูลชั้น ใช้ artwork.layout เป็นแนวทางพิกัด ใช้ scoring.score_track และ scoring.scenarios เป็นข้อมูลคะแนน ห้ามเดาหรือแต่งกติกาเพิ่ม ใช้ภาพ reference ที่แนบสำหรับลายโทเคน ฟอนต์ กรอบคะแนน และลายเส้น สร้างเป็นภาพสำเร็จทั้งใบแนวตั้ง 300:430, full bleed, มุมมนโปร่งใส Large คะแนนบนขวา Small คะแนนล่างขวา แสดง ×2/×3 เฉพาะ Small และเฉพาะกองหลายชั้น
